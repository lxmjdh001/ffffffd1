# 下载记录 UA 黑名单

在下载记录中展开“查看 UA”，即可拉黑或解除拉黑该 UA。黑名单属于当前账户，作用于其所有应用下载入口、详情页、下载请求、分流和斗篷入口；相同 UA 访问其他账户的资源不受影响，控制台登录也不受影响。

命中黑名单时复用斗篷的英文 “Account not found” 页面，返回真实 HTTP 404、禁止缓存，不跳转到斗篷配置的自定义安全页。旧下载凭证、HEAD 和分段续传同样检查，检查发生在创建归因/凭证、分流游标更新、文件读取或扣费之前。已经开始传输的请求继续使用原有完整性和结算逻辑。

匹配沿用下载记录的 UA 表示：清除 ASCII 控制字符并保留最多 2048 字节完整 UTF-8 内容，再比较整条 UA 的指纹；区分大小写，不进行关键词或通配符匹配。空值及纯空白 UA 不可拉黑。数据库只新增 `ua_blocks`，使用 `user_id + ua_hash` 复合主键，启动迁移可重复执行。

`PUT /api/downloads/{id}/ua-block` 接收必填的 `{ "blocked": true }` 或 `{ "blocked": false }`，返回 `{ "blocked": boolean }`。记录 ID 必须属于当前登录账户，写入需要 CSRF token；重复同一操作不会重复创建黑名单或审计。`GET /api/downloads` 在每行增加 `ua_blocked` 状态，仍按原日期和分页条件查询。

发布前备份 D1 数据库与配置，在 PostgreSQL 副本上验证仅增加 `ua_blocks` 表。更新服务端与前端后，检查同一 UA 在两个独立账户间的隔离、旧凭证续传拦截及解除恢复；不对真实用户下载记录执行测试拉黑。
