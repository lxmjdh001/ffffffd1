# DIY落地页

控制台菜单「落地页」展开后包含「DIY落地页」与「模版库」。「DIY落地页」打开代码与预览工作台。粘贴浏览器可运行的 HTML，设置名称，保存草稿或保存并发布。已发布页面可在 APK/PWA 创建、编辑和 APK 详情页设计中选择；同账号多个应用可以复用一个页面。

## 模版库与收藏

管理员通过「模版库管理」提前添加名称、说明和 HTML，配置适用 APK/PWA、平台主按钮和资源基址后保存上架；保存后系统自动用 Chromium 渲染真实页面并生成预览封面，无需上传封面或填写图片网址。支持编辑、下架和删除；编辑与上下架携带版本校验，避免覆盖其他管理员的新内容。

客户可在「模版库」预览并收藏。收藏会在客户账号下生成自己的已发布固定版本，不直接引用管理员账号的数据；同一个模版的重复收藏返回原快照。收藏和预览不生成应用访问或计费事件。

APK 新建、基础编辑、详情页设计及 PWA 创建、编辑共用 Google Play / DIY 两个选择卡，新建默认 Google Play。选择 DIY 后优先显示「我的收藏」，也可以切换「我的DIY」，或新标签打开 DIY 工作台、模版库并返回刷新。PWA 不再提供新的自定义图片/原有安装页选项；既有应用保留原配置，明确选择新模板后才替换。

管理员更新、下架或删除源模版，不会改变客户已收藏或已绑定的版本。「我的收藏」仍能查看、预览下架源的固定快照。取消收藏会保留应用绑定；未修改的快照归档，客户已经自行编辑过的内容继续作为个人 DIY 页面保留。

列表封面显示当前模版 HTML 的真实截图。生成期间显示「封面生成中」，失败时显示明确状态，客户仍可点击「预览」查看页面，管理员可点击「重新生成封面」。页面不会用示意图代替真实内容，也不再使用历史手动封面网址。收藏保留所收藏版本的封面，管理员修改源模版不会替换客户已有收藏的页面或封面。

## 应用内编辑页面内容

APK 新建、基础编辑、详情页设计，以及 PWA 新建、编辑中，选择收藏模版或自己的 DIY 页面后，可直接展开「编辑页面内容」，修改可见标题、正文、图片和主按钮文案，右侧实时预览修改后的真实页面。保存应用后生效；不必修改 HTML 或另外发布原页面。

这些修改单独保存在当前应用的落地页绑定中。同一个收藏或 DIY 已发布版本可以被多个应用复用，每个应用保留自己的内容；模版原稿、收藏快照及其他应用不会改变。更换页面或发布版本时清空原版本的内容覆盖；每项和全部内容都可以恢复原始值。已绑定的归档页面仍可修改当前应用内容，归档页面不能用于新的应用绑定。

字段从已发布 HTML 中自动识别，包括网页 `<title>`、可见标题、正文、`img` 和 CSS 背景图片；可用 `data-d1-label` 为原稿中的字段提供易读名称。“网页标题”用于浏览器标签，与页面里可见的大标题分别编辑；原稿没有 `<title>` 也可以新增，清空与恢复原稿是两个独立操作。公开 APK/PWA 会同步当前应用的网页标题；原稿没有标题且未单独设置时沿用应用名称，明确清空则保留空标题。

常见静态 HTML 的文字和按钮可以自动识别；脚本运行后动态生成的文字、CSS 伪元素文案、图片或 Canvas 中的文字不属于静态字段，可在 DIY 工作台调整原稿。普通文本按纯文字处理，图片支持 HTTPS 地址，或上传不超过 2 MiB、尺寸不超过 4096 像素且不超过 1600 万像素的 PNG/JPG/GIF/WebP。每页最多 201 个编辑字段，其中保留原有 199 个自动内容字段容量，并包含独立的网页标题和主按钮文案；旧的字段编号不变。单应用内容 JSON 最多 8 MiB。新增图片上传至 R2，应用内容只保存受控素材引用；原有内嵌图片继续兼容，不强制迁移。外部图片及默认缩略图经过已有的受控静态代理。

### 图片上传与 R2

图片编辑器通过 `POST /api/diy-landings/images` 上传原始图片，后端验证实际文件、尺寸、体积和动画帧资源限制后，使用签名 R2 请求保存原文件；保留 PNG/GIF/WebP 动画效果。优先复用独立的 `PAGE_IMAGE_R2_*` 配置，否则复用现有 `R2_*` 素材存储，不改变安装包的存储配置。无需新增桶或向前端提供密钥；没有 R2 配置时明确报错，不自动改为本地文件或 base64。

接口返回 `reference` 与 `preview_url`，格式为 `/return-flow-assets/{随机ID}.{图片格式}`；它是现有 R2 素材的受控访问引用，不是图片数据本身。上传的图片可以直接预览，公开 APK/PWA 则通过短期签名的 `managed-image` 资源入口读取，包括客户下载域名。保存或预览时检查图片归属，客户不能把其他账号上传的图片绑定到自己的应用；普通业务 URL 不会被当作图片代理访问。

素材复用现有账号的统一素材记录、100 个/500 MB 配额及 R2 对象登记。同账号相同图片按 SHA-256 去重；旧本地素材重新上传相同文件时会写入 R2，保留原引用地址及本地备份。上传、数据库登记或 R2 失败时，当前应用内容不变，未提交的 R2 对象会尝试清理。上传期间禁止保存或切换来源；过期上传响应不会覆盖新导入的配置。独立图片 R2 的对象使用当前环境下的 `d1apk/page-images/{环境标识}/diy/return-flow/` 子路径，现有 R2 素材回退使用自身 `d1apk/files/{环境标识}/return-flow/` 子路径，均不列举或删除共享桶中的其他项目文件。

主按钮只能编辑文案，不能在此填写跳转网址或改为其他应用。按钮固定使用当前 APK/PWA 的下载、安装、外跳、回流和计费流程；PWA 安装完成后仍由原运行时显示 Play。恢复原始文案时，预览和公开页面使用原 HTML 主按钮文字；原稿没有主按钮文字时使用下载/安装默认值。预览与内容编辑不触发应用访问、下载、安装或计费。

## 真实封面生成与运维

新增或修改模版 HTML、页面配置后，系统将渲染任务写入数据库，由后台工作进程异步生成封面。返回管理列表即可查看状态；等待完成后列表会更新截图。封面取自 390 × 844 手机视口下的真实 HTML/CSS/JS，PNG 上限为 3 MiB，并使用模拟应用数据；实际应用名称、图片和按钮状态仍以绑定应用为准。无需访问 APK/PWA 公开入口，因此生成、读取封面都不产生访问、下载、安装或计费记录。

任务、状态和 PNG 均保存在数据库中，多个控制节点共享封面，不依赖某台机器的本地截图文件。任务按内容指纹复用，旧任务的结果不会覆盖管理员刚保存的新版本。`control` / `all` 角色随原后台工作进程启动截图队列，每实例依次处理、每 2 秒检查新任务；多实例使用 90 秒数据库租约避免重复执行，中断后由其他实例接手。工作进程为浏览器期限额外保留 5 秒收尾时间，即默认 30 秒、配置最大 65 秒，始终短于租约。

封面读取需要登录，按当前管理员、上架源模版、收藏与固定版本快照检查权限；使用私有 ETag 缓存并在返回 `304` 前重新鉴权，避免退出或切换账号后沿用未校验的缓存。不向公共 CDN 开放用户封面接口。

一次任务最多尝试 3 次，失败后分别等待 10 秒、40 秒再自动重试；最终失败可在管理页点击「重新生成封面」（接口 `POST /api/admin/landing-templates/{id}/cover/retry`）。管理员再次保存模版时，对应的失败任务也会自动重新排队，即使 HTML 没有变化；已完成封面继续复用，正在生成的任务继续执行。列表提供 `cover_status=pending|processing|ready|failed` 及通用 `cover_error`，只有完成时才返回 `cover_url`；浏览器未安装或沙箱启动受限时，应先修复运行环境再重试。每小时清理超过 24 小时且已无模版、收藏或版本引用的封面。

迁移 v26 会为所有未删除源模版（包含下架模版）与既有收藏（包含源模版已删除的收藏）按各自固定源码自动排队补图，保留既有应用绑定。补齐过程不抓取历史手动封面 URL，期间可正常打开实时预览。

封面沿用项目现有的原生运行方式：本地通过 `start.sh → scripts/dev.sh → bin/d1apk`，线上通过现有 `d1apk.service`。截图队列在同一个应用进程中随 `control` / `all` 角色启动，无需额外渲染服务。`download` 角色不生成封面，也不要求安装浏览器。

本机需要 Chromium 或 Google Chrome。macOS 标准安装位置的 Chrome 可自动发现；自定义位置在 `.env.development` 中配置 `LANDING_SCREENSHOT_BROWSER`。启动脚本构建完成后会先执行一次真实截图检查，检查通过才启动控制端；失败时明确提示补齐浏览器或修改路径。已经运行的旧进程仍按原启动脚本规则复用，更新代码后需先按原方式停止旧进程，再重新启动。

Debian 原生服务器安装浏览器及中文、表情字体：

```sh
sudo apt-get update
sudo apt-get install --no-install-recommends chromium fonts-noto-cjk fonts-noto-color-emoji
sudo -u d1apk /opt/d1apk/current/bin/d1apk check-landing-browser
```

软件包以 Debian 官方 [Chromium](https://packages.debian.org/stable/chromium)、[Noto CJK](https://packages.debian.org/trixie/fonts-noto-cjk) 和 [Noto Emoji](https://packages.debian.org/trixie/fonts-noto-color-emoji) 为依据。诊断命令使用独立测试页面进行真实截图，不读取数据库、不生成业务访问或账单，也不需要加载生产密钥。可选浏览器配置与应用一致；若生产环境设置了自定义路径，应把同样的 `LANDING_SCREENSHOT_BROWSER` 传给诊断命令。浏览器或字体补齐后，在管理列表重新生成已失败的封面即可，无需重建模版或重新收藏。

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `LANDING_SCREENSHOT_BROWSER` | 空 | 自动查找 Chromium/Chrome；可填写可执行文件绝对路径。 |
| `LANDING_SCREENSHOT_NO_SANDBOX` | `false` | 原生服务保持 Chromium 沙箱，不使用 `--no-sandbox`。 |
| `LANDING_SCREENSHOT_TIMEOUT_SECONDS` | `25` | 单次生成期限，整数 10–60 秒；无效配置会阻止启动。 |

Linux 自动查找 `chromium`、`chromium-browser`、`google-chrome`、`google-chrome-stable`；macOS 同时支持标准安装位置的 Google Chrome。每次生成使用临时浏览器配置和独立调试管道，将浏览器 `HOME`、`XDG_CONFIG_HOME`、`XDG_CACHE_HOME` 指向该次临时目录，退出后清理；不会载入管理员登录态或原用户目录。渲染只允许内部临时页面及受控静态素材入口，素材仍执行私网、业务域、重定向、类型和大小限制。

线上继续使用 `d1apk` 非 root 服务账号与现有 systemd 加固项，包括 `NoNewPrivileges=true`、`PrivateTmp=true`、`ProtectSystem=strict` 和 `ProtectHome=true`；本功能不修改系统安全策略。`PrivateTmp` 提供截图所需的可写临时目录。部署前应在目标服务账号及相同运行限制下验证浏览器可用；若系统限制阻止浏览器沙箱，先检查诊断错误及发行版的浏览器运行要求，不关闭浏览器沙箱或现有服务加固项。浏览器缺失、启动受限或超时时只令封面任务失败，不停止既有下载、安装或账务流程。原生服务安装与验收步骤见 [NATIVE.md](NATIVE.md#template-library-cover-runtime)。

## 页面与版本

- 草稿修改不影响公开页面。发布生成不可变版本，应用锁定所选版本；升级需在应用中明确选择。
- 「我的落地页」管理复制、归档、引用与删除；被引用页面和版本不可删除。
- 原始代码最多 5 MiB；每账号最多 200 页，草稿与历史版本累计最多 100 MiB。
- `custom` 仍是原有自定义图片模板，DIY 使用独立的 `diy` 模式。
- 选择 DIY 的 APK 默认使用详情页入口；之后可以在下载设置中主动选择直下。显式 `/a/{slug}/direct` 继续直接下载。

## 按钮接入

推荐在客户代码里标记主按钮：

```html
<button type="button" data-d1-action="primary">
  <span data-d1-bind="primary-label">下载安装</span>
</button>
<h1 data-d1-bind="app-name">应用名称</h1>
```

也可以在工作台设置 `#download`、`.install-button`、`button.primary` 或 `[data-install]` 等基础选择器；支持逗号分隔。复杂后代/伪类选择器应简化，或改用上述标记。

常见的 `a.download-btn`、`a.install-button`、CTA 类名和明确的 `btn/button + primary` 组合会自动接入当前应用，兼容已有模版中已移除原始外链的下载按钮。`#details`、`#privacy` 等页内导航保持原作用；明确配置的主按钮选择器优先。

平台主按钮默认开启，可直接操作。点击隔离内容中的自定义按钮，会显示可信外层的继续按钮；访客再点击一次后调用原下载、安装或外部浏览器流程。该方式保留系统所需的真实用户手势，不把客户脚本消息当成计费授权。关闭平台按钮时，发布要求存在实际匹配的主按钮。

`window.D1Landing.primary()` 可以请求显示该继续操作。`data-d1-bind="primary-label"` 跟随父页面安装/Play/处理中状态；客户代码不能自行报告安装成功或已付费。

## 运行行为

客户 HTML/CSS/JS 在 opaque sandbox 中运行；可信父页面管理原有 APK 票据、PWA manifest/SW、安装确认、外跳签名、回流和业务状态。

- APK 继续按现有访问 UV 规则计费，详情访问和下载不重复扣费。
- PWA 开始安装时预留，仅浏览器真实 `appinstalled` 后结算；接受弹窗不等于安装完成，取消/失败/过期沿用原释放流程。
- 外跳 click/relay 沿用同一幂等事件；有效返回凭证仍避免第二次扣费。
- 回流、斗篷和推送保留当前免费规则及权限校验。
- 斗篷继续选择应用或 PWA，无需新增目标类型；即使地址是 `/c/{slug}`，内部接口与 SW 仍使用真实应用路径和当前合法域名。
- PWA `w2a_only`、自动 APK 下载、iOS 兼容、浏览器引导、Play、通知订阅和启动目标沿用应用设置；DIY 只替换安装入口内容。

## HTML 与素材兼容

支持完整 HTML 或片段、内联样式、隔离环境中的 JavaScript。原稿单独保留；渲染副本会阻止原页面的 base、manifest、嵌套框架、表单提交、自动顶层跳转等权限。

HTTPS 图片、CSS、字体、普通脚本及小型媒体通过有签名、短期有效的静态资源入口读取。相对地址需填写 HTTPS 资源基址。资源请求不携带后台 cookies；拒绝私网/保留网段、平台业务域、重定向、类型不匹配及超过 8 MiB 的响应。CSS `@import`、动态模块依赖、任意 Ajax、后端代码和构建项目不在支持范围。平台账号专属图片也不能当作永久共享素材使用，避免删除源应用后引用失效。

预览使用独立短时快照和模拟动作，不进入公开应用访问入口，不产生访问统计、下载票据、安装预留或账务记录。快照十分钟过期；每账号保留有限数量，刷新可重新生成。

## 迁移与发布

迁移 v24 新建 `diy_landing_pages`、`diy_landing_revisions`、`diy_landing_bindings`、`diy_landing_previews`；迁移 v25 新建 `landing_library_templates` 与 `landing_library_favorites`；迁移 v26 新建 `landing_covers` 和 `landing_cover_snapshots`，并为源模版与收藏固定关联封面内容指纹；迁移 v27 为应用绑定增加独立内容覆盖，旧绑定按无覆盖保留。封面表保存 PNG 和任务状态，快照表保留用户、收藏版本与封面的读取权限。迁移不自动绑定旧应用，不调整价格、余额、订单和历史结算；重复启动保留已发布内容与绑定。

APK 创建 multipart 与基础编辑可选字段 `landing_template=google_play` 表示主动选用 Google Play，省略时保留既有系统模板。`landing_source=diy` 继续使用客户自己的 `diy_landing` 引用，收藏内容不增加新的公开投放或计费入口。

控制端与下载端需同时发布支持 DIY 的后端，前端使用配套构建。动态 HTML/令牌/预览不进入 CDN；现有静态客户端脚本发布仍使用内容哈希与源站回退。更新 `pwa-client.js` 后须按既有启动发布流程生成新的静态脚本版本。

发布前备份数据库与数据目录，先在测试账号和测试应用验证。源码测试命令：

```sh
go test ./cmd/... ./internal/...
go vet ./cmd/... ./internal/...
npm --prefix web run test:deps
npm --prefix web test
npm --prefix web run build
```

本地 `artifacts/` 下的临时程序可能有多个入口，不作为产品 Go 包编译。独立 PostgreSQL 测试可通过既有 `TEST_DATABASE_URL` 测试机制运行，测试框架为每次测试建立独立 schema。

## 回退

单个页面回退：应用重新选择旧发布版本或系统模板。全局应急时配置 `DISABLE_DIY_LANDING=true` 并重启配套后端：停止新增/修改 DIY 内容及新绑定，公开入口显示受控的原下载/安装按钮，保留原业务设置和计费规则；已有引用可查询和解绑。恢复为 `false` 后重新启用。

缺失/损坏的引用同样回退到可信基础操作页，不静默选择最新版本。已有客户端可能继续执行已加载的页面，请按照现有票据有效期与业务状态控制访问。不要直接把不认识 `diy` 模式的旧二进制接到仍存在 DIY 绑定的库；先切换模式或使用兼容版本。回退不删除账务历史。
